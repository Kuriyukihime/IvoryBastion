## 0.25: engine reproduction and state identity

The active profile contained published 0.22 and local 0.24 DLLs. BepInEx skipped the old plugin, but both managed assemblies were still loaded. An isolated Unity run on the installed 1.5.0 game with RecalculateStats 1.7.0 showed a 0.24 cloned BastionController alongside a Body.mainStateType resolving to BastionMain from 0.22. This is a concrete failure: that state's GetComponent<BastionController> asks for a different CLR type, so it falls back to generic walking and cannot dispatch the custom kit. The earlier scale-only gravity hypothesis did not establish this cause. RecalculateStats 1.7 changes were inspected and were not the state-identity fault.

The native SerializableEntityStateType constructor stores an assembly-qualified string but does not seed its private _stateType cache.
